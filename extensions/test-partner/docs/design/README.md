## v1（后半段：已有用例 → 执行 → 结果）

## 怎么来的

六个面并行勘察 → 三个不同切入角各出一版设计 → 每版三个透镜独立评审 → 合成。

| 方案 | 切入角 | 得分 |
|---|---|---|
| B | 任务流：四步向导，不能跑的原因写在按钮旁 | 7.3 |
| A | 主从双栏：列表-详情，用例表与结果表合一 | 6.7 |
| C | 结果优先：首屏即上次结果，默认筛失败 | 6.0 |

**没有直接采用最高分的 B。** B 的四步向导对"重跑上次失败的几条"这个最高频动作太重——
要走完四步才能到结果。合成版取 A 的外壳（最像 DeepTutor 自己的页面）+ B 的阻断原因显式化
+ C 的结果优先默认。

## 三处刻意的设计决定

1. **用例表和结果表是同一张表**。一行在生命周期里换状态（待执行 → 执行中 → 通过/失败/跳过），
   不另开结果页。视线不用重定位，也不会出现"用例列表里的第 3 行"和"结果列表里的第 3 行"对不上。
2. **不能跑的原因写在按钮旁边**，不是点了才弹错。例：选中的用例里有一条没有断言，
   按钮置灰并直说「取消勾选它就能跑」。
3. **批次跑过就默认落在「失败」筛选**，没跑过才落在用例列表。日常最高频的动作是看上次哪儿挂了。

## 视觉与既有体系的关系

不是"设计了一套新的"，是**照抄 DeepTutor 的实测值**：

- 四套主题（Cream / Dark / Default / Glass）用 `globals.css` 的真实 token 值，class 驱动
- 页头结构照抄 `SpaceSectionHeader` 的真实 className（36px 圆角图标块 / `font-serif` 19px / 13px 描述）
- 状态色用仓里既有写法（`bg-emerald-500/10 text-emerald-600 dark:text-emerald-400` 这一族），不自造
- 字体 Geist + Lora，与全站一致

## 凭据

页面上只出现**环境名**，值由网关在本机解析。响应体里回显的凭证过脱敏后显示为 `{{token}}`。
这条在旧实现里已有硬断言守着，随迁。

# v2 · HAR 导入与用例生成（前半段）

## 对标结论（六路并行，许可证逐仓实核）

| 对象 | 开源 / 许可证 | 对我们的意义 |
|---|---|---|
| **MeterSphere** | 是，**GPLv3 + 附加条款**（FIT2CLOUD Open Source License） | **代码红线**：强 copyleft，拷进本私有衍生仓会传染分发义务；附加条款还禁止移除 logo/版权声明。**它的 AI prompt 是源码文件，同样受 GPL 覆盖，不能整段复制。** 交互设计层不受约束，可照着重新实现 |
| **Apifox** | 否，核心闭源；周边仓**无 LICENSE**（版权全保留，比 GPL 更严） | 零代码可抄。学交互自由，但**别照搬中文 UI 文案原句** |
| Keploy / mitmproxy2swagger | 部分（Keploy=Apache-2.0） | 流量转用例的去重与脱敏策略可参考 |
| Hoppscotch / Bruno / Insomnia | 全部开源且证干净（MIT 等） | Hoppscotch 有 HAR 导入 |
| AI 生成用例赛道 | 部分开源 | **没有一家把 HAR 和 AI 生成串成一条流水线**——这是我们的空间 |

## 明确借鉴了什么（点名）

- **勾选式采纳是入库的唯一闸门**（MeterSphere）：生成 ≠ 入库，不勾就不进用例库
- **prompt 用模板渲染真实端点结构，模型只填值**（MeterSphere）：把「AI 幻觉出不存在的字段」从架构上掐掉
- **生成配置的勾选 = prompt 模板的开关**（MeterSphere）：配置与 prompt 是同一份真相，不会漂移
- **分步生成的两段式人闸**（Apifox）：先只出用例清单让人改让人删，确认后才生成请求与断言——**改标题比改整条用例便宜十倍**
- **prompt 拆成结构化勾选 + 自然语言补充两层**（Apifox）：不给空白框，用户不知道该要什么

## 明确避开的坑

- **MeterSphere 的导入不给预览**：它在「接口变更同步」上做了完整 diff 确认，却在导入上一把梭，没有待导入清单、没有逐条勾选、连「新增 N 条」的回执都没有。HAR 是所有导入源里最脏的，恰恰最需要这道闸
- **MeterSphere 的 HAR 噪声治理几乎为零**：静态资源过滤只跳过几种后缀，请求头零黑白名单，HTTP/2 伪首部全进；有真实 issue 佐证。**我们把噪声治理做成体检的第一等公民**
- **MeterSphere 用哨兵字符串切分 LLM 输出**，导致生成一次 + 转换一次 = 两倍成本两倍延迟两处失败点
- **Apifox 自曝断言把数据转字符串**，`4 ≠ 4.0`
- **Apifox 的警告对我们最狠**：它自承认「接口文档越完善 AI 效果越好」，而它主输入是 OpenAPI（自带 schema/字段说明）。**HAR 没有 schema，只有一次调用的实例值——我们的 AI 输入质量天然更差。** 这是设计里「第 3 段先只出清单让人改」的直接理由

## 三条评审致命，逐条处置

1. **后端没有生成能力的落点**（已复核属实）：`extensions/test-partner/server/` 里零模型调用代码，
   网关只有 13 条路由，没有 HAR 上传/解析/生成/写用例任何一条。
   **架构决定：生成这一步交给 DeepTutor 的 agent，页面不自己造模型链路。**
   现状本来就是 agent 读 `skills/har-testing/SKILL.md` + 调 MCP 工具，页面只负责结构化的前后两端。
2. **脱敏契约不含 PII**（已复核属实，入 bug-bank **BB-424**）：
   界面**不得宣称「已全部脱敏」**。稿子里如实写：凭证已占位，个人信息不在范围内，分享产物前自查。
3. **界面指出问题却没有可操作控件**：待修的用例必须能就地改。稿子第 4 段每条 red 都带具体动作
   （「改成 /api/order/create」或「就地编辑」），不留死路。
