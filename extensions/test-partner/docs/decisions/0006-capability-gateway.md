# 0006 · 能力网关 + 本地配置中心（M3.5，立即实施）

- 日期：2026-08-05
- 拍板人：用户（UAT 二轮追问"逐能力脚本不可扩展、令牌为何不能页面配置"后定；要求先看体感再动工，已确认）

## 结论

1. **test-partner MCP 服务器升级为「能力网关」**：宿主机唯一常驻进程 = 唯一自启项。逐能力 cmd 脚本路线废止（现有 setup_tapd.cmd 网关落地后退役为排障工具）。
2. **本地配置页**：网关自带 Web 配置页，**只绑 127.0.0.1:3789**（局域网不可达）。所有凭据/连接（TAPD 令牌、未来的数据库 DSN、git 凭据、服务器配置）在页面填写、保存即生效；凭据只写宿主机本地配置文件，不进聊天、不进容器、不出宿主机。
3. **子服务管家**：网关代管 mcp-server-tapd 等子进程（按配置注入环境变量、启停/重启/状态），并负责把子服务注册进 DeepTutor（复用 register_tapd 的 API 调用）。
4. **扩展契约**：新能力 = 网关加工具 + 配置页加分区，零新脚本。blackbox 后续能力（数据库校验、git 取证、服务器操作）迁移一律走此骨架。
5. **团队形态**：每人本地装一次网关、各自页面配各自凭据——与 0003 审计条件（每人本地、令牌不共享）一致。
6. 开机自启做成 `scripts/install_autostart.cmd` 供用户自行执行（常驻配置由用户亲手启用，不代做）。

## 补记（0.6.1，2026-08-05）

配置页改成**按类型分四个 tab**（概览 / 连接与凭据 / 测试环境 / 测试伙伴），当前 tab 记进
URL hash。第 4 条的扩展契约随之细化：新能力优先并进已有 tab，只有独立成一类时才开新 tab
——分区堆成一个长页面的话，每加一个能力就多一屏滚动，这正是拍板要避免的。

### 内嵌形态

页面同时按「能被嵌进 DeepTutor 右侧 Viewer 面板」来做：`?embed=1` 去 chrome、
`prefers-color-scheme` 深浅色自适应、400–960px 自适应宽度。宿主的 iframe 沙箱
（`allow-scripts allow-same-origin allow-forms allow-popups`，`no-referrer`）带来三条
硬约束：不发 `X-Frame-Options` / `CSP: frame-ancestors`、不用原生弹窗、不做浏览器下载。
第 2 条的四道安全闸**一条不放开**——内嵌是同源回环访问，本来就满足。细节见 README
「把配置页嵌进 DeepTutor」一节与 `server/gateway/webapp.py` 模块 docstring。

## 补记（0.7.0，2026-08-05）

第五个 tab「工作台」（M3.6 第一版）。它是第 4 条扩展契约的第一次「独立成一类」——
批次 → 用例 → 执行 → 结果不属于任何一个既有 tab 的语义，并进去只会把那个 tab 撑坏。

一条边界要写死：**工作台不实现任何执行逻辑**。它进程内直接调 `server/execute.py` 的
`execute_cases`，凭据仍只以「环境名」的形式流动。另写一份 HTTP 客户端就等于把那四条
安全红线（跨 host 不发、变量缺失不发、凭据不出流、不判绿不猜）在第二个地方重新实现
一遍，两份实现迟早会漂——后续任何「在页面上跑点什么」的能力都照这条办。

同时给 `save_delivery` 加了无条件落盘的 `cases.json`：页面要把一批用例原样读回来，
而 xlsx 与 collection 都是**有损**的（前者丢 request 块，后者把断言编译成了 JS 文本）。
0.7.0 之前的批次没有这份文件，页面**明说降级**而不是从 collection 反推——
反解错了会静默地执行错的断言，比不给用更坏。
