# （已作废原文）0026 · TAPD 通道定型：接管 tapd-capability 双传输改造（3796），0012 落地形态更新

- 日期：2026-08-11

- 触发：用户另起会话推进 TAPD MCP（因误以为本线遗漏 TAPD），产出 3796 HTTP 通道；随后用户确认「TAPD 在后续计划中」并停掉该并行推进

## 事实澄清（TAPD 从未被遗漏）

TAPD 全链是 M2 主线，非附属项：工程设计稿 DoD **第 4 条**「从真实 TAPD 需求走完整链 → 拉取 → 快照+digest → 澄清 → 分析 → 用例 → 采纳 → 编译 → 执行 → 证据 → 覆盖图，≥8 条用例」被标注为 **M2 的主证据**；0023 锁定的靶需求 `1167600006001046281` 即为该条服务。用户「以为忘了」源于本线未就 TAPD 单独汇报进度，属 manager 汇报颗粒问题，非计划遗漏。

## 3796 是什么（当版实证，非转述）

不是新建服务，是工作区既有 TAPD 能力的**双传输改造**：

- 仓与提交：`tapd-capability` 已独立成仓（父仓 `43e6a0e` 停止跟踪），双传输改造同步指纹清单于 `c46a457`（上游 `3954b4c`）。
- 能力：`adapters/mcp_server.py:11` 声明 `streamable-http`（`--transport http`）「one process serving many people」；`:425` 明写**凭证按请求取自 HTTP 头，服务本身不持有任何人的凭证**；`:437-438` 为 http 模式入口。
- 即本线一直在用的权威 TAPD 能力（同一 server 的另一种传输），非 test-partner 网关自带的 2 工具子服务。

## 裁定

1. **M2 的 TAPD 通道采用 3796（tapd-capability streamable-http）**，替代旧 `:3795`（test-partner 网关托管的 2 工具子服务）。理由三条：
   - **服务端零凭据**——直接消解 P3 队列「TAPD 令牌迁移」「配置隔离改造」两项债，令牌不再落宿主配置文件；
   - **多用户上线形态**——用户已声明 DT 将部署线上供多人使用，per-request 令牌是该形态的必需，旧通道做不到；
   - **工具面 11 vs 2**——白盒 L3-L6 需要的查字段配置 / 查缺陷 / 基线核对只在权威能力侧。
2. **旧 3795 暂留不删**，待 3796 实测取到真实需求数据并跑通一次全链后再退役。退役时同步清理 test-partner 网关侧的 TAPD 令牌存储。
3. **归属**：该通道自本文起归吸收工程线维护，用户已停止并行推进。后续对它的改动走本线流程，不再另开会话推进，避免两线相撞。
4. **通道可切换是硬要求**（已下达施工）：端点与鉴权方式从配置读、不硬编码，鉴权支持请求头携带 Bearer。这既是本次切换的前提，也是上线形态的必需。

## 0012 落地形态更新（平账）

0012 原拍「TAPD 进容器 + stdio」。现实两次绕开：先是宿主 HTTP（网关托管），现为宿主 HTTP + per-request 令牌。

**更新**：0012 的**意图**（TAPD 能力对 DT 可用、令牌不散落）成立且已被更好地满足；其**落地形态**（进容器 + stdio）作废——根因是容器无法启动宿主进程，stdio 型 server 只能由客户端拉起子进程，该前提在容器部署下不成立。本文为 0012 落地形态的替代方案，0012 的其余条目（令牌不入代码、不入单页令牌框）继续有效且由本方案自动满足。
