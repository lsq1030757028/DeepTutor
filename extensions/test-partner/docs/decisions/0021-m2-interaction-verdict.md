## 总裁定

1. **聊天侧（§6a–6g）通过**，形态维持，不改。它做对的那件事是压缩：摘要级卡 + 「看的进聊天、改的进工作台」分工线。
2. **测试旅程工作台侧不通过**，判定为 0016 证伪信号触发——「看着像 DT 但用起来不顺」。按 0016 原文处置：**回信息架构层重做，不是调样式**。病因一句话：**工作台把工程产物模型未经压缩、按原样投影成了 UI**；聊天侧轻是因为压缩过，工作台侧重是因为没压。
3. 本结论**不重开任何已拍板项**：O1（两入口并列）、O3（列表第一眼口径）、O4（不做配置卡）、0019（载体=正式 Capability）、0020（预算 11）全部维持。压缩全部落在 T1/T2 薄壳内，**零新增上游触点**。

## 必改三条（信息架构层）

### 1. 账本九格 → 四段分组

九格是 `artifacts.py:195-207 stepper()` 的直译，不是用户心智。证据：后端现返 7 项，稿子为凑九格反过来要求后端补 2 项（稿 §2 fix 条）——UI 完整性倒逼工程量，是投影方向反了的信号。用户心智是四段：**接入与澄清 → 用例 → 执行 → 收口**。

- 改法：账本条显示四段，段内格子点开可见。
- **原则不动**：亮灭仍由产物存在性推导、不存 step 字段、无百分比、任意前缀是合法交付。该原则约束的是状态怎么来，不约束显示几格。
- 后端补执行/投影两项的施工要求维持（四段里「执行」「收口」的亮灭仍要读它们）。

### 2. 规则收敛为单一视图

R1–R12 现被投影三次：接入面段②澄清表（依据列）、段③分析面板（例子）、覆盖页签（覆盖状态）。同一实体认三遍，是「信息量大」体感的主要来源，且与本稿地基「批次是唯一状态对象」相悖——对象唯一，视图也该唯一。

- 改法：澄清表与覆盖表合并为一张规则表，依据 / 覆盖状态 / 关联用例三列并存；段③的例子与反例作为规则行展开。
- 不违反「三段折叠非向导」（0020 架构侧结论）：合并的是视图，不是把链路改成向导。
- 后端不动：`coverage.py:49-79` 三态数据与澄清产物各自照旧，合并发生在展示层。

### 3. 列表卡删九格微条

O3 拍的组织原则是「今天有什么要我处理，不是盘进度」，而九格微条是进度拓扑——它不要求用户做任何事，按 O3 自己的规矩就该降级。且稿 §1 why 条自认冗余（「文字和微条同时给」= 两个控件答一个问题）。

- 改法：卡上只留 lead 徽标 + 第二行灰字。进度拓扑只在详情页看。

## 建议两条（manager 可自决采否，不阻塞过稿）

4. 结果表「断到哪层」+「证据」两列合成一个证据强度信号，行展开见细节。防假绿语义不丢，扫读少一列。
5. 词表（旅程/批次/趟、三档、四结论+探测、收口、采纳=冻结、断层）约 10 个新概念——随用随教，首次出现处解释，不每屏全量摆出。M2 是单人 dogfood，词表可以慢慢立。

## 红线：压缩不许碰的信任机制

以下是本产品区别于普通测试工具的核心，复杂感里属于它们的部分是**必要成本**，任何一条在压缩中被削都算改错方向：

- 覆盖三态 + 逐行理由列（理由摊开显示，不进 tooltip）
- 探测项不进通过率分母，且与挂起严格分色
- 挂起必须带子因
- 写确认默认零勾选
- 结论落账后不可编辑（结论是投影不是人写的）
- 「没装」「装了但坏了」、「没跑起来」「跑了没过」等成对错误态分开说
