## 决策依据：视觉能力与链路的真实关系（当版实证）

用户的担心方向成立，但卡点不在执行环节。实证如下：

| 环节 | 是否需要视觉 | 证据 |
|---|---|---|
| 编译（ApprovedCaseSet → pytest+Playwright 工程） | 否 | `server/journey/compile_bundle.py` 无任何 llm/model/chat_completion 调用 |
| 执行 | 否 | `server/journey/execute_run.py` 同上，零 LLM 调用 |
| 元素定位 | 否 | `server/journey/pw_runtime.py:146` 走 selector，非图像识别 |
| 结论判定 | 否 | evidence-bundle → 机械闸投影；「判官不当闸」为硬纪律，模型不参与判定 |

**结论：纯文本模型（DeepSeek 等）在架构上不构成执行阻断。** 模型只承担前半段文本工作——读需求、抽规则、设计用例、产出执行配方。

## 三处真实视觉缺口（均不在执行环节，逐条处置）

1. **TAPD 需求正文内的原型图 / 截图**：纯文本模型读不了。
   处置：规则抽取以文字描述为准；仅图中存在的信息按既有机制标「探测性」，不进 PASS 判据（M1 已实现，不会假装看懂）。**本条对本次靶需求影响有限**（语音交互类需求以文字规则为主）。
2. **UI 用例的元素定位**：模型写 selector 需先知道页面结构。白月黑羽工序中的「页面快照 / site-map」原计划照迁，**M1 未实现**——当版核实 `server/` 内 snapshot 全部为 Playwright trace 证据用途（`pw_harness.py:64` tracing snapshots、`schema.py:26` 证据类型枚举），非喂给模型的页面结构。缺此能力时纯文本模型写 UI 用例等于盲写。
   处置：**本条即 UI 轨推迟 M3 的直接原因**；site-map 登记为 M3 前置能力。
3. **失败诊断读截图**：不影响结论正确性（结论为机械投影），仅影响根因文本质量。
   处置：不阻断，M2 接受根因文本质量降级。

## 为什么不选萌伴小程序改版（manager 上一轮推荐已撤回）

manager 首轮推荐 `1167600006001042649`（AI萌伴小程序改版）是**欠考虑**：该需求恰属 UI 类，会一头撞进上述缺口 2 这个未建能力。用户提问后重新核实才发现。记录此撤回以备复盘。

另：TAPD 队列 20 条中绝大多数为固件/端侧需求（小铁IP机器人、AI手办 ESP32、杭州JFB、唤醒词预研等），Playwright 无法驱动，本就出局——可选面比预期窄得多。
