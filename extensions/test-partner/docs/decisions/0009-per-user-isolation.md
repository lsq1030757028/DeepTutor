# 0009 · 工作台数据每用户隔离

- 日期：2026-08-07
- 拍板人：用户
- 原话：`各看各的`（回答「工作台数据是每用户隔离还是全员共享」）
- 反馈落盘：[2026-08-07-design-v2-har.md](../feedback/2026-08-07-design-v2-har.md)

## 结论

**测试工作台的数据每用户隔离**：交付批次、用例、执行记录，各人只看得到自己的。

## 为什么这一条要单独立决策

它不是 UI 偏好，它决定三件工程上的事，而且这三件在代码写下去之后改都很贵：

### 一 · 鉴权档位

上一轮勘察给的建议是后端挂 `_admin`（管理员限定），**前提假设是「工作台数据是共享资产」**。
该假设已被本条推翻，故建议同步作废。

隔离形态下应走**普通登录档**（`dependencies=_auth`），不是管理员档——
每个登录用户都能用，只是各自看各自的。

> 勘察同时给了一条硬约束：router **绝不能裸挂**（不带 `dependencies`）。
> 不装 ContextVar 会让落盘数据**静默写到 admin 工作区且不报错**
> （`deeptutor/services/auth.py:230-232`）。隔离形态下这条从"不整洁"升级为"串数据"。

### 二 · 落盘路径

现役 `deliveries/` 是**单一平铺目录**，没有用户维度。隔离形态要求产物按用户分区。
这一步做不干净，就是「A 能在批次列表里看到 B 的用例」——
而用例里带着 B 那份 HAR 的实例值（含 PII，见 BB-424）。

**因此本条与 BB-424 是叠加风险，不是两件独立的事。**

### 三 · 执行记录与凭据

执行用的是「环境名」，环境与变量金库现在也是全局的一份。
隔离形态下要回答：环境是每人一份，还是共享环境、只隔离批次与结果？
**本条不裁定这一项**——用户回答的是"工作台数据"，环境金库是否同隔离未被问及，
留待明确，不擅自扩大解释。

## 待办（不在本条范围，登记在此以免遗漏）

- `deliveries/` 目录分区方案与既有批次的迁移口径
- 环境与变量金库是否同隔离（须另问用户，勿自行裁定）
