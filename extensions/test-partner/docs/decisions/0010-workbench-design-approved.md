## 定稿过程中被用户推翻过的设计（记下来，免得实现时走回头路）

| 我方原设计 | 被否原因 | 定稿形态 |
|---|---|---|
| 用户在端点表里逐个勾选要测的端点 | 一份 HAR 几百个接口，把 AI 的苦力活外抛给人 | **AI 挑，结果给人看、可调，不用人动手** |
| 场景描述做成五字段表单（业务场景/前置条件/要重点验的/不测什么/数据约束） | 「用户也不知道」什么叫数据约束；降低心智负担的手段被做成增加负担的形式 | **一个文本框，AI 起草大白话，范本 = 示范不是表格** |
| 场景 prompt 放在配置页 | 它是测试能力不是配置项 | **回到生成流程第 3 步** |
| 测试环境与 TAPD 令牌平铺在同一配置页 | 局部配置与公共配置是两个层级，压平了 | **局部留工作台，公共进 Settings** |
| 屏序：采纳 → 执行 → 导出 | 语义上暗示"必须先跑才能导"，且强迫用户在采纳时就决定跑不跑 | **采纳即终点；导出与执行平级，顺序任意、可只做一个、可反复做** |
| 「SVG 场景图」当成新功能写进规划 | 用户说的是导出入口的类别图标，我凭空造了个需求 | **四种导出各配文件类型图标** |

## 实现时必须带着的三条约束

1. **界面不得宣称「已全部脱敏」**——凭证已占位，PII 不在脱敏范围内（BB-424，open）。
   稿子第 2 屏那段如实声明必须原样落地。
2. **勾选是入库的唯一闸门**——生成 ≠ 入库。
3. **红色必须带可操作的出路**——界面指出问题却不给控件，比不指出更堵。
