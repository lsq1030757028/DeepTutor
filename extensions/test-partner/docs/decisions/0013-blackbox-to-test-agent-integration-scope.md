## 用户原话

> 1、HAR本质上是通过工具＋AI快速生成接口自动化脚本，追求的是快，且HAR依赖的是人工操作，而不是需求，这里接需求天然不匹配，还会导致整体产出路径拉长，扩大未知风险；
>
> 2、DT项目的二次开发，重心是要移植blackbox的那套测试工具，其中就包括拉需求、分析、产出用例，缺的是AI执行自动化测试的流程，我让你看白夜黑羽项目的目的，就是让你分析它的项目实现跟我们已有的这套test_agent如何通过工程化实现进行结合。

## 冻结边界

1. HAR 是独立快车道：输入来自人工操作所形成的流量证据，不把需求拉取、需求分析前置到 HAR 路径。
2. DeepTutor 二次开发的主线是承接 Blackbox 已有的需求获取、需求分析和测试用例产出工具。
3. 主线当前缺口是把已确认用例工程化为可运行自动化，并接入 test_agent 的真实执行、证据、判定和回归闭环。
4. 白月黑羽方案用于研究“已有用例之后如何组织 AI 自动化开发”，不用于证明“需求应接 HAR”。
