# 0016 · M2 测试工作台界面 mood：跟齐 DeepTutor 现有风格

- 日期：2026-08-11
- 决策人：用户（mood 人闸，不可代拍）
- 用户原话选项：**「跟齐 DeepTutor 现有风格」**——与 DT 主体同一套设计语言，看上去就是 DT 的一个原生功能页，不出现第二套观感。
- 触发：用户查看 M1 交付时指出「我以为的设计稿是指交互稿」，暴露 M1 设计闸缺口。

## 背景：M1 的流程缺口（如实记录）

M1 设计闸只产出**工程设计稿**（架构/拓扑/数据契约），界面部分仅 §4 一段文字方案，**未出任何逐屏交互稿、未走 mood 人闸**。
manager 当时的判断依据是设计闸卡 0 拍板「复用 ask_user、不新建聊天组件」，据此认为新界面面很小——**该判断错误**：
施工实际产出了完整的批次工作台页面（`server/gateway/journey_console.py` 内嵌 `_PAGE`），零设计输入。
成品见 `agent-lab-runs/deeptutor-absorb-m1-20260810/evidence/workbench-{batch-list,coverage-and-results}.png`：功能齐备但纯默认样式。

违反的既有共识：「UI 审美先定 mood」「验收=用户体验不是测试报告」。

## 裁定

1. M1 的 gateway 批次页**降级为内部调试面**，不作为用户界面交付物。
2. M2 的 `(workspace)` 前端薄壳（用户已于 0015 拍板的落点）是真正的用户界面，**必须先出交互稿 → 用户过稿 → 再实现**，不得再由施工直接生成界面。
3. 交互稿 mood = 跟齐 DT 现有设计语言：复用 DT 的色板/间距/圆角/组件形态与导航语义，不自创第二套视觉体系。

## 实现约束（交互稿与实现共同遵守）

- **禁用 `[var(--x)]/alpha` 透明度写法**：DT 上游存在已确认缺陷——Tailwind v3.4 对 `text-[var(--muted-foreground)]/60` 这类写法生成不出 CSS（变量是十六进制色值无法做 alpha 分解），全仓 1003 处命中，导致次要文字全部以全强度显示、视觉层次塌陷（见 `DEV_STATUS.md` 共享资源节，圆桌线运行态+静态双实证）。
  跟齐风格时**必须用真实色 token + `opacity-*`**，不得复制该坏写法。
- i18n parity 强制：新增文案 `web/locales/{en,zh}/app.json` 成对增加。
- 上游触点预算沿用护栏 6，交互稿须标注每屏落点是新增文件还是上游触点。

## 证伪信号

若用户在交互稿评审时表示「看着像 DT 但用起来不顺」，说明 mood 对齐做成了皮肤套用而非信息架构对齐，需回到信息架构层重做而非调样式。
