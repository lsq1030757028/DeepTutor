# 0028 · 写确认必须补齐；定档时序按实现走并上浮；两处稿-实现偏离登记

- 日期：2026-08-11
- 决策人：manager 自决（机制选择）
- 触发：M2 卡片层施工报出两处「人闸能弹、答案无处可去」

## 一、写确认：必须补 `journey_write_confirm`，不接受「限制说明」形态

**事实**（无截断枚举，施工方实测）：`write_confirm` 事件全仓**无任何生产写入口**——生产侧 `append_event` 只产出 `adopt_confirm` / `tier_confirm` / `tool_call` / `gate_token_used` 四种，聊天侧无对应 MCP 工具、工作台亦无；而 `pw_runtime.py:88` 在执行时会查它，查不到即拦。

**后果**：写确认卡可弹、用户可答「全部允许」，写用例照样被拦并报「未获写确认授权」。这是 BB-502 的形状——挂一个兑现不了的承诺。

**裁定：补齐，不接受停在「提示词里写明限制」这个形态。** 两条理由：

1. **它是用户已拍板的四类人闸之一**（0015 卡 0）。人闸的定义是「用户在此处的决定能改变系统行为」；答案落不进任何地方的卡不是人闸，是征询意见的装饰。
2. **它直接卡住 M2 主证据**。0023 锁定的靶需求是《Queenie 新建自定义角色支持韩语语音交互及男女音色》——**"新建角色"本身就是写操作**。写确认不通，主证据里最核心的那批用例永远执行不了，DoD#4 无从判分。

**落点**：`journey_write_confirm` 工具建在 extensions 侧（m2-build2 独占区），**0 上游触点**。施工方在提示词里加的限制段与「不许说已授权」的约束**在补齐前保留**——它是诚实降级，补齐后随删除条件一并移除。

## 二、定档时序：按实现走（ingest 之前问），登记为稿-实现偏离

**事实**：`tier` 在 `journey_ingest` 那一刻即冻进 `intake_profile`（`ingest.py:147` 落 `tier_confirm` 事件），**事后无改档工具**。

**裁定**：
1. **定档卡在 ingest 之前问**（施工方已如此实现）——照稿「接入完成时弹」做，答案落不进任何地方，那是第二个假授权。**实现优先于稿的字面**。
2. **不补改档工具**。档位决定测试深度，中途改档会使下游产物（分析、用例、编译产物）的档位前提失效；强制重走接入在语义上是正确的，不是缺陷。
3. 稿中「之后可以改但要重新生成」这句**当前兑现不了**（无改档工具），与第 2 条合并处理：语义上「改档 = 重新接入」，UAT 时向用户说明这一口径。

## 三、两处稿-实现偏离，UAT 时单列呈报（不得并进「已按稿实现」）

本决策新增两条，连同此前已登记的两条，UAT 清单中的稿-实现偏离共 **4 条**：

| # | 稿上是什么 | 实现是什么 | 为什么 |
|---|---|---|---|
| 1 | 接入面 s5 独立页签 | 挂在账本页签下 | 施工方判断，manager 未代批（前案） |
| 2 | 流式卡单次调用内 `7 / 约 12` 计数跳动 | 跨工具真增量，单次调用内计数不变 | 后端 replace 语义；补发射器需动 MCP 半成品回传，工程量远超收益（前案） |

**呈报形态统一为**「原稿是 X ／实现为 Y ／因为 Z」的对照，每条单列。

## 五、方法论沉淀（本轮第五、六例）

- **「取数对了 ≠ 界面会出现」**：单元判据四张卡全绿，SSR 渲染判据第一次跑就红——`batch_id` 只有 ingest 放顶层、其余工具盖在产物信封里，导致四张卡的「去工作台」按钮全部渲染成灰的点不动。**单元判据与渲染判据不是详略之分，是看不看得见不同东西。**
- **拿业务词当"未出现"的判据会假红**：原以「覆盖」二字判断覆盖卡未出现，而规则卡的边界说明里就含「不覆盖声明」。**判据要锚在标识常量上，不锚在会出现在别处的自然语言里。**
- **性能判据配一条不依赖计时的确定性证明**：逐 tick 喂 300 事件断累加器 `examined == 300`（全量重解析会是 45150）。计时会抖，这条不会——**凡性能断言，尽量同时给一条结构性证明。**
