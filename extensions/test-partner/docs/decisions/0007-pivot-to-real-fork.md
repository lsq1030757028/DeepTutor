# 0007 · 路线修正：从「外挂式插件」转为「真二开（fork DeepTutor）」

- 日期：2026-08-05
- 拍板人：用户

> 是的 我认为应该是真二开，而且我们开发流程可能存在问题，我们需要规范 github 产品发布和回归基线，以便后续能持续迭代和回滚

## 背景：割裂是怎么产生的

因果链（每一步单看都成立，合起来必然分叉）：

1. 决策 0001 定红线「只写插件、不改 DeepTutor 内核」，理由是保住上游演进红利。
2. M0 实机摸底：v1.5.8 未发布 `deeptutor.plugins`，官方可用扩展面只有 MCP 服务 / SKILL.md / 伙伴人格——
   三者**全部只喂聊天**，没有任何 UI 扩展面（MCP 返回值被压成纯文本，markdown 白名单转义 iframe，
   唯一结构化卡片 `ask_user` 是内置的）。
3. M3.6 用户要求「不想基于会话体验」，需要固定工作流的交互。在红线约束下，界面只能长在自研网页里。
4. 配置页（`:3789`）因此从「填令牌的页面」长成「工作台」——批次/用例/执行/结果这条产品主动作全部
   发生在我们这一侧，DeepTutor 退化为 iframe 宿主。**第二个主产品就此诞生。**

**根因**：技术上并非不可行；是「不改内核」这条为旧形态（聊天内调工具）定的红线，
在需求变为「要一个真界面」之后没有被重新审视，与「无 UI 扩展点」这一事实叠加，
数学上只能推出「另起一个前端」。红线本身没错，错在没随形态变更而重估。

## 拍板结论

1. **路线改为真二开**：fork `HKUDS/DeepTutor`（Apache-2.0），工作台作为 DeepTutor 界面内的原生页面实现，
   配置并入其中。目标是**一个产品、一个入口**，不再有并排的第二个前端。
2. **「不改内核」红线撤销**，替换为可持续跟随上游的工程纪律（详见待定的 0008）：
   改动以新增文件为主，对既有文件的修改集中、少量、可标记，`upstream` 定期同步。
3. **MCP 面保留**：聊天链路（TAPD 需求→用例，用户已实测跑通）继续经 MCP 提供；
   工作台改为前端直连后端 API，不再绕 MCP 传结构化数据。
4. **已交付资产的处置基调**：服务端能力（`parse_har` / `validate_cases` / `save_delivery` /
   `execute_cases`，含 600 例离线测试与四条执行安全红线）是资产，随迁不重写；
   自研单页前端（原生 JS）随迁到 DeepTutor 设计系统重写——沿用它才不割裂。
5. **发布与回归基线须先于大规模代码搬迁落地**（用户同轮提出）：当前 49 个提交无远端、无 tag、无 CI，
   在无基线状态下做架构级搬迁，无法自证「没搬坏」。具体方案见 0008。
