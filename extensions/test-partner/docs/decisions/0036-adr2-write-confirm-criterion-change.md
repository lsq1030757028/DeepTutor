# 0036 · ADR-2 波及：写确认「必须真实生效」的判定口径变更（同步 Queenie 线）

- 日期：2026-08-19 · 来源：`vibe-flow/runs/deeptutor-test-positioning-20260818/`
  （spec r3 + decisions.md ADR-2，用户已拍板）· 性质：**口径同步记录**，不是新裁决
- 授权链：ADR-2 用户拍板「采纳是唯一硬闸，采纳卡升级到同等授权强度」；
  本记录履行该 spec 下游交接事项 1（「0029 口径变更须同步 Queenie 线所有者」）。

## 变的是什么

`0029:51` 施工约束原文：「写确认人闸必须真实生效（`journey_write_confirm` 已于
`7bb7864a` 落地，BB-511）」。

**判定口径由「独立卡形态」变更为「决定经采纳卡验签落账」**：

- 用户不再在写授权点单独作答；写授权决定合并进采纳卡（ADR-2）。
- 授权强度不降：采纳卡决定令牌绑该批写用例的内容摘要集、经 `decision_auth`
  验签、jti 防重放；用例内容改动后旧授权自动失效（AC7）。
- `write_confirm` 事件照落（由采纳派生，`via="adopt_card"`，2026-08-19 Delta
  裁决复用事件类型不新增）；`execute_run.write_authorization` 的取数口不变。
- `journey_write_confirm` 工具在过渡期保留（兼容工作台面）；聊天旅程不再要求
  模型弹独立写确认卡。

## 不变的是什么（0029 其余三条约束原样有效）

写只落测试环境 / cleanup 声明强制非空、不宣称自动回滚 / DB 层一律只读。

## 对 Queenie 线的影响

以「独立写确认卡是否弹出」为判据的用例/断言，判据应改查
「events.jsonl 含经验签的 `write_confirm` 事件（`via="adopt_card"` 或
`ask_user_card`）且绑 `source_case_digest`」。**卡形态不再是必要条件，
验签落账才是。**

## 证伪信号

若施工实际以放宽校验落地（任一：不绑内容摘要 / 不验签 / 不防重放），
触发 `0025` 重开条件，本口径变更作废，回 ADR-2 重议。
