- [ ] （TAPD 链路需要）浏览器打开 **http://localhost:3789**，切到**「连接与凭据」tab**（或直接开 http://localhost:3789/#credentials），在「TAPD 访问令牌」里粘贴你的 TAPD 个人访问令牌，点「保存并生效」，看四步全绿即可——写本机配置、起 TAPD 子服务、注册进 DeepTutor 部署注册表（只放行 `get_stories_or_tasks` / `get_stories_fields_info` 两个只读工具）、回读连接状态，全自动，DeepTutor 页面上不用点任何东西。输入框是 password 型（不明文显示），令牌不回显、不进日志、不经聊天传递。可随便重存（幂等），换令牌就直接贴新的。注意：令牌错误或网络不通时子服务会**起不来**（官方包在启动时即校验），页面会按启动日志给出分类诊断。
  - 兜底：配置页本身起不来时，回退用 `tapd-runtime\setup_tapd.cmd`（已退役为排障工具，仍可用）。
- [ ] （要在产品内执行用例才需要）浏览器打开 **http://localhost:3789**，切到**「测试环境」tab**（或直接开 http://localhost:3789/#environments）点「新增环境」配一个被测环境：环境名（例如「测试环境」）、`base_url`（形如 `https://api-test.example.com`）、以及用例里 `{{token}}` / `{{session}}` 这类变量的真值（值输入框是 password 型）。保存后列表里只显示变量的**键名与掩码**，值不回显。
  - 这是 0.6 的重点：配过一次之后，聊天里**只说环境名**就能执行，凭据由网关在你本机解析——不进聊天记录、不进模型上下文、不出这台机器。**不要再在聊天框里贴 token。**
  - 值存在 `config\environments.json`（与 `secrets.env` 同等对待，不进版本库）。改环境时值输入框留空 = 保留原值，删掉整行才会删掉那个变量。
- [ ] （伙伴门面）在 **http://localhost:3789/#partner** 的「测试伙伴」tab 点一次「创建/修复测试伙伴」——人格正文、MCP 工具、两份技能、中文回复一次配齐，逐步回显 √/×。已经手工建过伙伴的，在「目标伙伴」下拉里选「修复现有」，它只做增量补齐，不删不改名。手工路径与真实界面字段名见 `partner/README.md` 附录 A。

- [ ] （可选，体感更顺）把配置页嵌进 DeepTutor：在「概览」tab 点「复制链接」拿到 `[打开测试伙伴工作台](http://127.0.0.1:3789)` 这一行 markdown，贴进聊天（或写进伙伴的 SOUL 提示词）。点它会在**右侧 Viewer 面板**里打开配置页，不用再切浏览器标签页。想更贴合面板可以用 `http://127.0.0.1:3789/?embed=1#environments` 这种带参数的形式：`?embed=1` 去掉大标题那一块只留内容主体，`#` 后面直接指定开在哪个 tab。页面深浅色跟随宿主，面板拖到最窄（400px）也不塌。
  - 面板里的限制（不是缺陷，是 iframe 沙箱给的）：**没有浏览器弹窗、没有下载**。所以删除环境是页面内的行内确认条，产物一律给绝对路径 + 「复制路径」按钮。

**运维已知项**：重启网关后，聊天侧会话不会自动跟进——否则聊天里调用会报 Session terminated（设置页显示 Connected 不代表聊天侧会话活着）。现在不用再去 MCP 服务页手工拨开关了：配置页**「概览」tab** 的「维护动作」里点**「刷新聊天会话」**即可。聊天输入框**回车不发送**，要点发送按钮。

## UAT-1 · HAR → 可执行接口用例（核心链路）

素材：一份真实业务 HAR（浏览器 F12 → 网络 → 导出 HAR），放入 `D:\Test_Coding\test-partner\inbox\`。

步骤：DeepTutor 聊天（或测试伙伴）里说"用 inbox 里的 xxx.har 生成接口测试用例"。

| # | 验收点 | 通过判据 |
|---|---|---|
| 1 | 体检摘要 | 端点数/业务域/鉴权方式/可回放档位用业务语言汇报，无机器字段直出 |
| 2 | 脱敏 | 全程（含聊天回显与产物）不出现任何 token/cookie/口令值 |
| 3 | 人闸 | 生成前确认范围/深度，答完能继续（偶发失稳时发"继续"可恢复） |
| 4 | 用例质量 | 场景级、六字段齐、覆盖你确认的范围、含异常场景 |
| 5 | 双产物 | `deliveries/<时间戳-标题>/` 下同时有 cases.xlsx 与 *.postman_collection.json + receipt.json |
| 6 | 可执行（产品内，凭证不经聊天） | 落盘后它会问"要不要当场执行"，并**列出配置页里已配好的环境让你选**（不会向你索要 token；一个环境都没配时它引导你去配置页配，而不是让你在聊天里贴凭证）。选定环境后真发请求、逐断言比对，汇报几过几败几跳过 + 执行报告路径；凭据值不出现在聊天、返回值与报告里，报告只记环境名与 host。执行范围默认是本批全部用例，少跑要有你明说的理由。**体检判为档A（可重登录）时它应当优先建议「登录换新」**：让你在配置页那个环境里配一次 `login_username` / `login_password`，之后每轮执行前自动重登录换新 token，不用再手工贴过期的 token；执行报告里多一行「凭据来源」写明本轮是登录换新拿的凭证与登录端点路径（不含任何值）。档B或识别不出登录请求时走原来的环境变量路线，不会硬推 |
| 7 | 可执行（外部） | collection 导入 Apifox（或 Postman）后结构正确（模块分组、请求参数、断言脚本），改 baseUrl 后可发起执行 |
| 8 | 收据 | receipt.json 记录输入指纹、校验结果、产物 sha256 |
