# 测试伙伴门面（partner/）

这个目录放的是 DeepTutor 侧「伙伴」的配置素材，不是代码。

| 文件 | 用途 |
| --- | --- |
| `SOUL.md` | 人格正文。**分隔线以下**的部分会被注入伙伴，分隔线以上是给我们自己看的说明 |

技能剧本不在这里，在 `skills/`（`har-testing`、`req-testing`）。

---

## 主路径：配置页点一下

1. 宿主机起网关：`scripts\start_server.cmd`（已装开机自启的话它本来就在跑）。
2. 浏览器开 <http://localhost:3789>。
3. 先看顶部「运行状态」：`DeepTutor · test-partner` 那一格得是 **connected**。
   不是的话先解决它——网关没连上 DeepTutor 时，伙伴挂不到任何工具。
4. 拉到「测试伙伴」分区：
   - 还没有伙伴 → 「目标伙伴」保持「新建『测试伙伴』」，名字想改就改，点 **创建/修复测试伙伴**。
   - 已经手工建过一个 → 在「目标伙伴」下拉里选**修复现有：<你的伙伴>**，再点同一个按钮。
5. 按钮下面会逐条回显 √/×：读人格正文 → 清点工具 → 建/改伙伴 → 写人格 → 绑技能 → 回读核对。
   全绿就完事了。

这一下做了什么：

| 项 | 值 |
| --- | --- |
| 人格 | `SOUL.md` 分隔线以下的正文，`[伙伴名字：待用户起名]` 自动替换成伙伴名 |
| MCP 工具 | `test-partner` 的**全部**工具；`tapd` 注册了就再加 `get_stories_or_tasks`、`get_stories_fields_info` 两个只读工具 |
| 技能 | `har-testing`、`req-testing` 复制进伙伴工作区 |
| 语言 | 中文 |

几条它**不做**的事，写在这里免得你担心：

- 不删伙伴、不改名。选「修复现有」时只做增量：你自己额外挂的 MCP 工具会保留，
  伙伴原有的技能不会被清掉。
- 重复点没有副作用。第二次点，回显会变成「已是最新／无需改写」，落盘状态一个字节不动。
- 不替你选模型。伙伴的模型留空 = 用系统默认；想指定就去伙伴的设置里自己选。

### 修完确认一眼

去 DeepTutor 的「伙伴」页打开这个伙伴，对三处：

- 灵魂：正文开头是 `## 我是谁`，不是 `# Soul` 也不是 `# SOUL — Hermes …`。
- 工具：`MCP 工具` 里 `test-partner` 的几个是勾上的。
- 技能：`资料库` 里有 `har-testing`、`req-testing`。

> 伙伴详情里那个「人格来源」标签，修复既有伙伴后仍会显示原来的值（比如 `library / hermes`）。
> 那是**创建时的出处记录**，DeepTutor 运行时读的是伙伴工作区里的 `SOUL.md` 正文——
> 也就是刚被覆盖掉的那份。以灵魂编辑器里显示的正文为准。

最后做一次冒烟：让伙伴调 `ping`，返回 `{"server": "test-partner", "status": "ok"}` 就算通了。

## 附录 A · 手工路径（DeepTutor v1.5.8 实测）

配置页起不来时的兜底。字段名对着 v1.5.8 的真实界面写，不同版本可能有出入。

新建伙伴的向导有五步：**1 身份 → 2 灵魂 → 3 心智 → 4 资料库 → 5 审阅**。

### 1 身份

「这个伙伴是谁？」

- **名称**：随便起，`测试伙伴` 就行。
- **描述**：可留空。
- **形象**：随便挑个 emoji。
- **回复语言**：选 **中文**（默认是「自动（English）」，不改的话伙伴可能拿英文回你）。

### 2 灵魂

这一步有三个页签：**灵魂库** / **克隆 Persona** / **自己撰写**。

> ⚠️ **进这一步的瞬间，向导会自动替你选中灵魂库里的第一个模板**（本机上是 `hermes`），
> 下面的编辑器里显示的就是那个模板的正文。这是最容易踩的坑——见附录 B。

正确做法：

1. 点 **自己撰写** 页签。
2. 把编辑器里的内容**全选删掉**。
3. 打开仓库的 `partner/SOUL.md`，复制第一条 `---` 分隔线**以下**的全部内容，粘进去。
   分隔线以上那三行说明不要粘。
4. 把正文里的 `[伙伴名字：待用户起名]` 换成第 1 步起的名字。
5. 确认编辑器里第一行是 `## 我是谁`。**如果还看得到 `# SOUL — Hermes`，说明没替换干净，回第 2 步。**

### 3 心智

「它思考用的模型，以及允许使用的工具。」

- **模型**：留空即用系统默认。
- **系统工具** / **内置工具**：不用管。
- **MCP 工具**：这一栏是本次的重点。勾上：
  - `test-partner` 名下的**全部**工具（`ping`、`server_info`、`parse_har`、
    `validate_cases`、`save_delivery`、`execute_cases`）；
  - `tapd` 名下**只勾两个只读的**：`get_stories_or_tasks`、`get_stories_fields_info`。
    这个包 43 个工具里 17 个是写操作，凭据是模块级单例，写操作在 TAPD 审计里追不到人。
    `tapd` 整个不出现是正常的——没注册而已，HAR 链路不依赖它。

  这一栏空着，就是本次缺陷里那个 `mcp_tools=[]`：伙伴一个工具都调不了，
  只能在聊天里给草稿、落不了盘。

### 4 资料库

「选中的内容会复制进伙伴的私有工作区。」

在 **技能** 里勾上 `har-testing` 和 `req-testing`。

注意这里是**复制**，不是引用：技能不勾就等于伙伴没有，全局有这份技能也没用。
（也因为是复制，之后改了 `skills/` 里的 SKILL.md，得回来重新走一次一键修复。）

### 5 审阅

对一眼再点 **创建伙伴**。

### 建完之后想改

伙伴详情页里改：

- 灵魂 → 编辑正文后点 **保存 SOUL.md**。
- 工具 → 在 **MCP 工具** 里勾，提示「工具已更新——下一条消息起生效」。
- 技能 → 在 **派生资源** 里加。

## 附录 B · 上一版指引为什么会做错

上一版 README 写的是「新建伙伴 → 粘 SOUL → 勾工具策略」三步。三步全都对不上真实界面：

| 上一版说 | 实际是 |
| --- | --- |
| 「粘进向导的『灵魂』步骤」 | 灵魂步骤**预先替你选中了灵魂库第一个模板**。不主动切到「自己撰写」并清空，粘不进去或被覆盖 |
| 「伙伴的工具策略里启用 test-partner MCP 服务器」 | 界面上没有「按服务器启用」这回事，**MCP 工具是一个一个勾的**。而且这一栏默认全空 |
| 「技能：两份 SKILL.md」 | 技能在**第 4 步「资料库」**里勾，是复制进伙伴工作区。上一版没说在哪一步，也没说它不是全局生效 |

实机核对的结果就是这三条各错一处：`soul_origin={"type":"library","id":"hermes"}`、
`mcp_tools=[]`、技能没绑。三样恰好是「这个伙伴能不能干活」的全部，所以那个伙伴干不了活。

一键按钮就是为了让这三样不再依赖人的手速——它调的是同一组 API，
逻辑在 `server/gateway/partner_setup.py`，字段形状是对着本机实例实测抄的。
